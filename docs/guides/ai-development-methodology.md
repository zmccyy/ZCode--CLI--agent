## 工具组合策略

### 主力工具：Claude Code + DeepSeek

DeepSeek 系列模型作为主力开发模型，负责 80%+ 的日常开发工作：

- **代码编写与修改**：通过 Claude Code 的 Edit/Write 工具直接修改源文件
- **测试驱动开发**：每次代码变更后立即运行测试验证
- **批量重构**：利用 Agent 工具并行探索多个子系统后统一修改
- **Bug 修复**：从错误日志定位根因，逐层追踪调用链

**为什么选择 DeepSeek 作为主力：**
- 上下文窗口大，适合大型代码库探索
- 工具调用稳定，适合 Agent 循环
- 中文理解能力强，适合中文需求文档理解

### 辅助工具：Codex App + GPT 5.4

GPT 5.4 作为辅助验证模型，用于：

- **代码审查**：对关键模块变更进行独立审查
- **架构验证**：将设计方案交由 GPT 5.4 评估合理性
- **测试用例生成**：补充边界条件和异常路径测试

### 设计工具：Claude Code + Opus 4.6

Opus 4.6 用于需要深度推理的任务：

- **详细计划编写**：602 行开发计划由 Opus 4.6 主导编写
- **架构权衡分析**：复杂技术决策的多方案对比
- **风险预判**：识别技术难点和集成风险

## 协作流程

### 标准开发流程

```
用户提出需求（自然语言）
       ↓
AI 阅读代码库（Glob/Grep/Read 工具）
       ↓
Plan 模式 — 设计方案 → 用户审核确认
       ↓
AI 逐步骤实施（Write/Edit + 测试）
       ↓
用户审查 → 反馈 → AI 修正
       ↓
Git 提交 → 进入下一个任务
```

### 关键实践

1. **Plan 模式先行** — 复杂任务（预计 > 3 步）必须先用 Plan 模式设计方案，用户确认后再编码。避免方向性返工。

2. **增量实施** — 大功能拆分为可独立验证的小步骤。每步改 1-3 个文件，改完立即测试。

3. **测试驱动** — 代码变更后立即运行 `bun test`。测试失败不进入下一步。

4. **并行探索** — 需要理解多个子系统时，使用多个 Explore Agent 并行搜索，汇总结果后再决策。

5. **上下文管理** — 长会话使用 `/compact` 压缩上下文。关键决策写入项目 memory 供后续会话参考。

## 会话管理模式

### 单任务会话（推荐）

```
/clear  →  新会话开始
用户描述单个任务（如"修复 XX bug"）
AI 探索 → Plan → 实施 → 测试 → 提交
会话结束
```

### 长会话（多任务连续）

```
用户设定大目标（如"/goal 完成9-15"）
AI 创建 Task 列表追踪进度
AI 逐个任务执行
每完成一个任务标记 completed
全部完成后用户审查
```

**长会话适用场景：**
- 关联性强的多个任务（共享上下文减少重复探索）
- 持续重构（需要记住之前的改动）

**风险：** 上下文窗口可能溢出。使用 Task 列表追踪进度，必要时 `/compact`。

### 断点续作

```
会话 1：完成任务 1-8
会话 1 上下文窗口接近上限
       ↓
启动新会话 2 → 系统自动提供会话 1 摘要
会话 2：继续完成任务 9-15
```

Claude Code 的会话续作机制会自动总结前一会话的关键信息（任务进度、修改的文件、待解决问题），使新会话能快速接续。

## AI 工具使用技巧

### Prompt 编写

- **明确输出格式**：要求 AI 输出文件路径而非长篇解释
- **设定边界**：明确哪些文件不要改、哪些模式不要用
- **提供上下文**：引用具体文件路径和行号，而非模糊描述

### 工具选择

| 场景 | 推荐工具 | 原因 |
|------|----------|------|
| 代码探索 | Glob + Grep (直接) | 速度快，结果精确 |
| 大范围搜索 | Agent (Explore) | 并行搜索，汇总去重 |
| 设计讨论 | Agent (Plan) | 结构化输出，方案对比 |
| 代码修改 | Edit | 只传输 diff，节省上下文 |
| 新文件创建 | Write | 一次性写入完整内容 |

### 常见陷阱

- **不要同时改太多文件**：超过 5 个文件容易出现遗漏或冲突
- **不要跳过测试**：AI 写的代码正确率约 85-90%，测试是最后防线
- **不要忽略 Plan 模式**：跳过设计直接编码的返工率是 Plan 模式的 3 倍
- **保持会话聚焦**：一个会话一个主题，避免话题跳跃

## 实际案例

### 案例 1：REPL 启动链路打通（T2.2）

**任务**：创建直通适配器绕过 OpenAI 格式转换

**AI 使用方式：**
1. 3 个 Explore Agent 并行分析 CLI 入口、Provider 运行时、REPL 消息流
2. 人工决策：确认需要新适配器而非修改现有代码
3. Claude Code (DeepSeek-V4-Pro) 创建 `anthropicAdapterClient.ts`（354 行）
4. 编写测试 `anthropicAdapterClient.test.js`（562 行，12 项）
5. 运行测试 → 发现 `.js` → `.ts` 导入问题 → AI 修复
6. 再次测试 → 95/96 通过

**关键经验**：并行探索 + Plan 模式先定方案，避免无效编码。

### 案例 2：功能 9-15 批量开发

**任务**：完成 REPL TUI 改进计划中的 7 个功能（Task 9-15）

**AI 使用方式：**
1. 会话 1 完成任务 7-11，上下文窗口接近上限
2. 会话 2 续作，系统提供前一会话摘要（修改的文件、任务进度）
3. Claude Code 逐个任务执行：读取文件 → 理解现有实现 → 判断是否需要修改 → 实施
4. 每个任务完成后标记 completed

**关键经验**：
- 很多计划中的功能已有成熟实现（如 diff 展示、LSP 诊断追踪），只需补充设置开关或调参数
- 先读代码再判断是否需要改，避免重复造轮子
- 会话续作机制保障了 15 个任务跨 2 个会话的连贯性

## 工具配置参考

### Claude Code 配置

```bash
# 使用 DeepSeek 模型
export ZCODE_PROVIDER=openai-compatible
export ZCODE_OPENAI_PROVIDER=deepseek
export ZCODE_OPENAI_MODEL=deepseek-chat
export ZCODE_OPENAI_BASE_URL=https://api.deepseek.com/v1
export ZCODE_OPENAI_API_KEY=your-key

# 或使用 Anthropic 模型
export ANTHROPIC_API_KEY=your-key
claude --model claude-opus-4-7
```

### Codex App 配置

Codex App 作为辅助工具，在需要独立审查时通过 Web 界面使用 GPT 5.4 模型，不参与主开发流程。
